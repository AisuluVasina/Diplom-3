# Дипломная работа. Часть 3
## Задание 3. Автотесты для UI

### Назначение тестов
Автотесты предназначены для проверки корректности работы пользовательского интерфейса (UI) сервиса Stellar Burgers: валидации переходов между разделами, взаимодействия с ингредиентами, отображения модальных окон и корректности счётчиков и ленты заказов. Тесты реализованы с использованием паттерна Page Object для структурирования локаторов и действий на страницах.

### Что тестируется
Тестируются сценарии взаимодействия пользователя с веб‑интерфейсом Stellar Burgers в браузерах Google Chrome и Mozilla Firefox. Отчётность формируется в Allure.

* **Основная функциональность и навигация** (tests/test_main_functionality.py)
    * `test_navigate_to_constructor` — проверка перехода по клику на раздел «Конструктор»;
    * `test_navigate_to_order_feed` — проверка перехода по клику на раздел «Лента заказов»;
    * `test_ingredient_modal_open` — при клике на карточку ингредиента появляется всплывающее окно с деталями;
    * `test_ingredient_modal_close` — всплывающее окно закрывается при клике по крестику;
    * `test_ingredient_counter_increase` — при добавлении ингредиента в заказ счётчик этого ингредиента увеличивается.

* **Раздел «Лента заказов» и статистика** (tests/test_order_feed.py)
    * `test_total_counter_increase_on_order` — при создании нового заказа счётчик «Выполнено за всё время» увеличивается;
    * `test_today_counter_increase_on_order` — при создании нового заказа счётчик «Выполнено за сегодня» увеличивается;
    * `test_order_appears_in_work_section` — после оформления заказа его номер отображается в разделе «В работе».

#### Для покрытия сценариев использованы:
- **Page Object Pattern** — инкапсуляция локаторов и методов взаимодействия для повышения читаемости и поддерживаемости тестов:
    - `pages/base_page.py` — базовые методы (поиск элементов, клики, ожидания);
    - `pages/login_page.py` — логика авторизации (используется в фикстурах для подготовки сессии);
    - `pages/main_page.py` — элементы главной страницы и навигация;
    - `pages/constructor_page.py` — работа с конструктором бургера и ингредиентами;
    - `pages/feed_page.py` — элементы ленты заказов;
    - `pages/order_feed_page.py` — детализированная работа с разделом «Лента заказов» и счётчиками.
- **WebDriverWait и явные ожидания** — для стабильной работы тестов в Chrome и Firefox, включая проверку видимости элементов и появления текста.
- **фикстуры** (`conftest.py`) — для инициализации драйвера, перехода на стартовую страницу и очистки состояния между тестами.
- **параметризация** (`@pytest.mark.parametrize`) — для компактного тестирования нескольких ингредиентов или комбинаций действий.

### Структура проекта
- `pages/` — классы Page Object для каждой страницы (`base_page`, `login_page`, `main_page`, `constructor_page`, `feed_page`, `order_feed_page`);
- `tests/` — pytest‑тесты с Allure‑метками (`test_main_functionality.py`, `test_order_feed.py`);
- `conftest.py` — фикстуры для инициализации браузера и общих шагов;
- `locators.py` — централизованное хранение локаторов элементов;
- `data.py`, `generators.py`, `helpers.py` — вспомогательные утилиты и тестовые данные;
- `config.py` — базовые URL и константы;
- `requirements.txt` — зависимости проекта (selenium, pytest, allure, webdriver-manager и др.).

### Запуск тестов
1. Установите зависимости:  
   `pip install -r requirements.txt`
2. Запустите тесты в Chrome:  
   `pytest tests/ -v --alluredir=allure-results --browser=chrome`
3. Запустите тесты в Firefox:  
   `pytest tests/ -v --alluredir=allure-results --browser=firefox`
4. Сформируйте Allure‑отчёт:  
   `allure generate allure-results -o allure-report --clean`
5. Откройте отчёт:  
   Откройте файл `allure-report/index.html` в браузере.
